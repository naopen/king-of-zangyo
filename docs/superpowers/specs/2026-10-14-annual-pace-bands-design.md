# 年間残業の色分けを、年度の残りに応じて動かす

2026-10-14 にNaokiと壁打ちして決めた内容。モックは `mock/annual-pace-mock.html`。

## なぜ変えるか

いまの年間の色分けは累計時間の固定値で決まる（300hで黄、330hで赤、360hで濃赤）。4月から毎月45hの人だと、黄が点くのは10月20日ごろになる。この時点で360hに収めるには、残りを月11h程度に落とす必要がある。月20hへの切り替えは7月末、月10hへの切り替えは9月末までに始めないと間に合わないので、黄が点いた時点ではどちらも遅い。

累計180hでも、7月末なら余裕があり、2月末なら危ない。固定の閾値では「まだ間に合うか」を表せないので、年度の残りに応じて境目を動かす。

加えて、年間のデータはユーザーが「最新データで更新」を押したときにしか更新されない。押し忘れを見込んで、早めに知らせる。

## 決めたこと

### 境目の式

経過月数を t（0〜12、小数）とする。

| 境目 | 式 | 意味 |
|---|---|---|
| 緑と黄の境目 | 360 − 20 ×（12 − t + 1） | 年360hまでの残り枠が「残りの月数×20h＋20h」を切る |
| 黄と赤の境目 | 360 − 10 ×（12 − t） | 年360hまでの残り枠が「残りの月数×10h」を切る |
| 赤と濃赤の境目 | 360 | 変えない |
| 濃赤と紫の境目 | 540 | 変えない |

計算した境目は整数の時間に切り捨て、判定も切り捨てた値で行う。凡例に「192h」と書いてあるのに192:30で緑のまま、という食い違いを防ぐため。切り捨てなので、黄と赤は最大1時間早く点く。

黄の式に足した「＋1か月」は20h分の余裕でしかない。45h/月の人が黄を見たあと1か月気づかずに過ごすと、その1か月で20h/月より25h多く積むので、月20hに落としても収まらない（45hを5か月続けてから20hにすると年365h）。月10hに落とせば収まる（同じく年295h）。このため凡例やREADMEの説明に「1か月遅れても月20hで収まる」とは書かない。

### 経過月数の数え方

- 基準日は今日ではなく、保存データの最終更新日（`lastUpdated`、`2026/08/20 18:05` の形式）にする。数字と色が同じ時点の情報になり、境目が動くのはボタンを押して取り直したときだけになる
- 年度開始月は今の設定ではなく、保存データの `fiscalYearStart` を使う。保存したあとで設定を変えても、その年度の月の数え方は保存時のままだから
- 経過月数は日割りで数える。最終更新日の月が年度の何か月目かに、その日の終わりまでを日割りで足す（8月20日なら 4 + 20/31）。最終更新日が年度の始まりより前なら0とする

整数で数えると次の不具合が出るので採らなかった。当月を含めて数えると、45h/月の人が7月31日に黄、8月1日に緑と、月替わりで色が行き来する。当月を含めずに数えると、黄が点くのが8月下旬になって20h/月の切り替えに間に合わず、年度の最終月は残り0か月になって黄と赤の帯が消える。

### 例（モックで計算した値）

最終更新日ごとの境目。

| 最終更新日 | 残り月数 | 緑 | 黄 | 赤 |
|---|---|---|---|---|
| 2026/07/31 | 8.000 | ～180h | 180～280h | 280～360h |
| 2026/08/10 | 7.677 | ～186h | 186～283h | 283～360h |
| 2026/08/20 | 7.355 | ～192h | 192～286h | 286～360h |
| 2026/12/31 | 3.000 | ～280h | 280～330h | 330～360h |
| 2027/02/28 | 1.000 | ～320h | 320～350h | 350～360h |
| 2027/03/15 | 0.516 | ～329h | 329～354h | 354～360h |
| 2027/03/31 | 0.000 | ～340h | 340～360h | （出さない） |

毎月同じ時間を残業した人が、毎日ボタンを押した場合に色が変わる日。

| 毎月の残業 | 黄になる日 | 赤になる日 | いまの固定閾値の場合 |
|---|---|---|---|
| 45h | 2026/07/31（180:00） | 2026/10/27（309:12） | 黄は10月20日ごろ、赤は11月上旬 |
| 30h（年360hちょうどのペース） | 2027/01/29（298:04） | 2027/03/30（359:02） | 黄は1月末、赤は2月末 |
| 25h | ならない | ならない | ならない |

### 年度の最終日と過去の年度

- 黄と赤の境目が360hに達した日（年度の最終日）は、幅0の赤の帯を凡例に出さない。「360～360h」と出るのを防ぐ
- 最終更新日が年度の終わり（年度開始月から12か月後の1日）以降なら、その年度は終わったものとして扱う。帯は緑（～360h）、濃赤（360～540h(超過)）、紫（540h+(特別条項超過)）の3つにする。終わった年度で知りたいのは360hを超えたかどうかだけなので、黄と赤は出さない

### 古い形式のデータ

`lastUpdated` か `fiscalYearStart` が無い保存データは、年度開始月の機能を足したコミット `44eee55` より前に保存されたもの。この場合は今の固定閾値（300h/330h/360h/540h）で表示する。ボタンを押して取り直せば新しい形式で保存されるので、次の表示から新方式になる。

### 凡例

凡例の見た目は今と同じ（帯5つを1行に並べ、今いる帯を太字と下線で示す）。帯の表示名だけ、その時点の境目で作り直す。2026/08/20に取得した場合は次のとおり。

```
～192h  192～286h  286～360h  360～540h(超過)  540h+(特別条項超過)
```

各帯の `title` 属性（マウスを乗せると出る文）は次のとおり。

| 帯 | 今年度 | 過去の年度 |
|---|---|---|
| 緑 | 年360hまでの残り枠が、残りの月を月20hずつ使っても20h以上余る見込みです。 | 年360h（36協定の上限）以内に収まっています。 |
| 黄 | 年360hまでの残り枠が「残りの月数×20h＋20h」を切る見込みです。残りを月20h以内にすれば収まりますが、余裕は20h未満です。 | （帯なし） |
| 赤 | 年360hまでの残り枠が「残りの月数×10h」を切る見込みです。残りの月を月10h未満にしないと、年360hを超えます。 | （帯なし） |
| 濃赤 | 年360h（36協定の上限）を超えています。 | 同じ |
| 紫 | 年540h（36協定の特別条項の上限）を超えています。 | 同じ |

古い形式のデータを固定閾値で表示しているときは、`title` を付けない。

### 完了ダイアログ

境目が動くのは取り直したときだけなので、そのとき必ず出る完了ダイアログで知らせる。今の表示（見出し「完了」、年間の色の背景に「正常に取得が完了しました。」と年間残業時間）の下、色の背景の外に次を足す。

```
年度の残日数に合わせ、凡例を更新しました（2026/08/20 時点）
  緑↔黄  192h
  黄↔赤  286h
```

- 変更前の境目は出さない
- 上書き前の保存データが古い形式だったときだけ、最後に「年度の残りに応じて境目が動くようになりました。」を1行足す
- 過去の年度を取得したときは何も足さない。ダイアログは今と同じ見た目になる
- 日付は最終更新日の日付部分

ダイアログの背景色も新方式の帯の色にする。

### `annual-pace.js` の関数

入力は保存データ（`totalMinutes`、`lastUpdated`、`fiscalYearStart`）と年度（`fiscalYear`、保存キーの年度）だけで、今日の日付は使わない。同じ入力なら必ず同じ結果を返す。

```
computeAnnualBands(annualData, fiscalYear)
  → {
      kind: "pace" | "finished" | "legacy",
      thresholds: { yellow, red, crimson: 360, purple: 540 },  // finished では yellow, red は null
      bandIndex,          // 0〜4。totalMinutes から判定
      legend: [{ colorIndex, label, title }],  // 凡例に並べる帯。幅0の赤と、finished の黄と赤は含めない
      asOf: "2026/08/20", // 最終更新日の日付部分
    }

buildBandsNotice(bands, previousAnnualData)
  → 完了ダイアログに足す文字列。足すものが無ければ空文字
```

色のコード（`#c8e6c9` など5色）は今の `ANNUAL_BANDS` と同じ値を `annual-pace.js` に移す。文字色（540h以上で白）を決める `getAnnualOvertimeTextColor` は帯の番号で判定する形に直す。

ブラウザでは関数をグローバルに置き、Nodeでは `module.exports` で渡す。

```js
if (typeof module !== "undefined") {
  module.exports = { computeAnnualBands, buildBandsNotice };
}
```

`content.js` から `annual-pace.js` の関数が見えることは、Chromeの公式ドキュメントで確かめられなかった（`js` 配列の順に注入されることだけが書いてある）。実装の最初に、拡張を読み込んで実測する。見えなければ、`annual-pace.js` から `globalThis` に明示的に置く形に変える。

### 完了ダイアログで前の保存データを読む

`completeFetchAnnualOvertime` は `saveAnnualData` で上書きする前に `loadAnnualData(targetFiscalYear)` で前のデータを読み、`showResultDialog` に渡す。前のデータは古い形式かどうかの判定にだけ使う。

## テスト

`node --test tests/` で `annual-pace.js` を読み込んで検証する。依存パッケージは入れない（Node 22.18.0 で動作する標準機能）。

- 上の「最終更新日ごとの境目」の7行が一致する
- 上の「色が変わる日」の表が一致する（45h、30h、25h）
- 45h/月の人で、2026/07/31と2026/08/01の帯が同じ（黄）。月替わりで色が行き来しない
- 2027/03/31は凡例に赤の帯が無い
- 年度開始月が1月と10月のとき、年をまたぐ月の経過月数が合う
- 最終更新日が年度の終わり以降なら `kind` が `finished` で、凡例が3つ
- 最終更新日が年度の始まりより前なら t=0 として計算する
- `lastUpdated` か `fiscalYearStart` が無ければ `kind` が `legacy` で、境目が300h/330h
- 境目ちょうどの時間（192:00）は上の帯に入り、191:59は下の帯に入る
- `buildBandsNotice` が、新しい形式、前のデータなし、前のデータが古い形式、過去の年度の4通りで想定の文字列を返す

画面の確認は、拡張機能をChromeに読み込み、KING OF TIMEのタイムカード画面で年別データの表示と完了ダイアログを見る。

## やらないこと

- 月間の色分けは変えない
- 「1か月遅れても月20hで収まる」を保証する式（余裕を45hにする案）は採らない
- 今日の日付を基準に境目を動かすことはしない
